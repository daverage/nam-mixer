## Summary of Findings

### B3-1: Hard Gate Silently Skipped (CRITICAL)

**Status:** CONFIRMED (by code inspection)

Both local (`scripts/train_a2.py` lines 276-278) and cloud (`cloud/kaggle/train_a2_cloud.py` lines 301-303) implementations return `{}` and skip the hard gate if `branch_samples` is empty.

Trigger scenarios:
1. Hybrid/Character mode with missing `design.envelope_max_history_ms`
2. Any mode with unreachable amp paths
3. Cloud with missing `receptive_field.branch_samples` in manifest

**Impact:** Training proceeds without RF verification when CORE RF cannot be determined. A2 trained on impossible function. Safety-critical.

**Why it's hard to hit in practice:** 
- Bundles generated by `hybrid.modes.training_target` should always have complete manifest
- But a manually edited/corrupted manifest could trigger this
- Parity tests use complete manifests, don't test the edge case

**Recommendation:** BLOCK release until fixed. This is a hard gate that must never silently skip.

### B3-2: Parity Gap if Local Load Fails (MEDIUM)

**Status:** PLAUSIBLE (edge case not covered by parity tests)

If local trainer's `load_nam()` fails on one amp but manifest has the recorded RF value:
- Local: skips that amp (prints warning), computes hard_required from remaining amps
- Cloud: reads all recorded values from manifest

Divergence possible if:
1. Manifest has "Amp A": 6000 samples, "Amp B": 3000 samples
2. Local load_nam("Amp A") fails (file corrupted)
3. Local computes hard_required = 3000 (only Amp B)
4. Cloud computes hard_required = 6000 (reads both from manifest)
5. Training allowed locally, rejected on cloud (or vice versa)

**Why it's hard to hit in practice:**
- Parity tests use synthetic .nam files that load successfully
- Real bundles are self-contained with all .nam files
- But if .nam file is deleted or corrupted after bundle generation, could trigger

**Current parity test:** `test_receptive_field_parity.py` does NOT test "manifest has data but load fails"

**Recommendation:** Add test case, then decide if we want to:
- (A) Trust manifest over load failure (simpler, less robust)
- (B) Always fail if load fails (stricter, safer)

### B3-3: Cabinet FIR Approximation Warning Missing (LOW)

**Status:** PLAUSIBLE (edge case with missing IR data)

If baked cabinet's IR file is missing AND manifest has no FIR data:
- `_resolve_baked_cab_fir_samples()` returns `(0, None)`
- Function returns early (line 354-355, both local and cloud)
- `result["cab_baked"]` still True, but no warning printed
- User unaware cabinet was not actually applied

**Why it's hard to hit in practice:**
- `hybrid.modes.training_target.maybe_bake_cab()` saves both IR file and manifest record
- Bundles are self-contained
- But if IR file is deleted after bundle generation, could trigger

**Impact:** Low — baked cabinet is an optional feature. If data is missing, A2 trains without it (still valid, just not what user intended).

**Recommendation:** Low priority. Add warning message or fail explicitly, but not critical.
