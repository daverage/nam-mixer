Absolutely. Here is a detailed build prompt you can hand to Claude/Codex for the next phase of `hybrid-nam-builder`.

> Extend the existing `daverage/hybrid-nam-builder` project with a new, more deterministic **Character Blend** mode.
>
> This is not GP50/CLO work. This is about creating a **pure Full A2 NAM** that combines the characteristics of two source NAM amplifiers in a controlled, explainable way.
>
> The current project already has:
>
> * **Dynamic Hybrid**: level-driven crossfade from Amp A to Amp B;
> * **Fixed Blend**: constant waveform mix:
>
> ```python
> result = A * (1 - mix_b) + B * mix_b
> ```
>
> The current Fixed Blend is useful as a baseline, but it is too naive for the real goal. It simply sums two level-matched amp outputs and hopes that the resulting waveform represents a meaningful "blend" of the two amplifiers.
>
> The new mode should instead create a deliberately designed hybrid amplifier whose **tone, dynamic feel, compression, gain behaviour and nonlinear character** are derived from the two source NAMs in a deterministic way.
>
> ---
>
> ## Core design goal
>
> Given:
>
> ```text
> Amp A = Fender-style amp
> Amp B = Marshall-style amp
> ```
>
> we want to be able to create something like:
>
> ```text
> low input:
> mostly Fender character
>
> medium input:
> genuine mixture of Fender and Marshall behaviour
>
> high input:
> increasingly Marshall-like gain/compression/nonlinearity
>
> while the overall EQ can remain a deliberate blend
> rather than simply switching fully from one amp to the other
> ```
>
> Or alternatively:
>
> ```text
> Tone:
> 70% Fender
>
> Feel/compression:
> 50% Fender / 50% Marshall
>
> Drive/nonlinearity:
> 75% Marshall
> ```
>
> The objective is to create a **new coherent amplifier**, not merely parallel-mix two existing outputs.
>
> ---
>
> # Preserve existing modes
>
> Do not remove or silently change the behaviour of:
>
> ```text
> Dynamic Hybrid
> Fixed Blend
> ```
>
> Keep the current Fixed Blend exactly as a baseline/reference mode.
>
> Conceptually:
>
> ```text
> Dynamic Hybrid
> = Amp A at low level → Amp B at high level
>
> Parallel Blend
> = current fixed waveform mix
>
> Character Blend
> = deliberately interpolated amplifier characteristics
> ```
>
> It is acceptable to rename the current UI label `Fixed Blend` to `Parallel Blend`, but preserve its API/implementation compatibility unless there is a strong reason not to.
>
> ---
>
> # Main architectural principle
>
> Do NOT build Character Blend as:
>
> ```python
> target = A * x + B * (1 - x)
> ```
>
> That is specifically what we are trying to move beyond.
>
> Instead:
>
> 1. analyse each source amp;
> 2. derive measurable characteristics;
> 3. interpolate those characteristics according to user controls;
> 4. construct a deterministic teacher target from those derived targets;
> 5. train one A2 NAM against that teacher.
>
> The system should be explainable enough that we can say:
>
> > This model is 65% Amp A in broad EQ, 40% Amp A in dynamic feel, and 20% Amp A / 80% Amp B in drive character.
>

>
> # Phase 2 — broad frequency-response character
>
> Character Blend should explicitly derive each amp's broad EQ response.
>
> Measure magnitude response at multiple input levels.
>
> Do not attempt to match raw FFT bins directly.
>
> Use:
>
> ```text
> log-frequency bins
> broad smoothing
> approximately 1/3 to 1/2 octave resolution
> ```
>
> Suggested useful frequency range:
>
> ```text
> 80 Hz – 10 kHz
> ```
>
> with optional taper/ignore outside that range.
>
> For each input level:
>
> ```text
> EQ_A(level, f)
> EQ_B(level, f)
> ```
>
> Derive a target EQ in dB:
>
> ```text
> EQ_target(level, f)
>     = EQ_A(level, f) * tone_mix_A
>     + EQ_B(level, f) * tone_mix_B
> ```
>
> where:
>
> ```text
> tone_mix_A + tone_mix_B = 1
> ```
>
> This is interpolation in **log magnitude / dB**, not linear waveform amplitude.
>
> The purpose is to create an intentional spectral midpoint rather than whatever spectral cancellation/boost happens when two differently phased waveforms are summed.
>
> ---
>
> # Phase 3 — dynamic feel / compression curve
>
> Measure each amplifier's level transfer behaviour.
>
> For each probe input level:
>
> ```text
> input RMS
> output RMS
> output/input gain
> ```
>
> Example conceptual result:
>
> ```text
> Input    Fender gain    Marshall gain
> -18 dB      +6 dB          +5 dB
> -12 dB      +6 dB          +5 dB
>  -6 dB      +5 dB          +3 dB
>   0 dB      +2 dB          -1 dB
>  +6 dB      -3 dB          -5 dB
> ```
>
> This curve captures:
>
> ```text
> headroom
> compression
> saturation onset
> response to picking strength
> ```
>
> Interpolate this independently:
>
> ```text
> GainTarget(level)
>     = GainA(level) * feel_mix_A
>     + GainB(level) * feel_mix_B
> ```
>
> Use interpolation between measured levels so the target curve is smooth.
>
> Do not force every source amp to have the same output RMS before analysis, because their dynamic transfer behaviour is itself part of the characteristic.
>
> Normalisation for comparison may be done around a defined reference level, but preserve relative nonlinear gain behaviour across input level.
>
> ---
>
> # Phase 4 — nonlinear / drive character
>
> This is the hardest part and should be implemented conservatively.
>
> Do NOT initially attempt to mathematically decompose an A2 model into literal circuit-style nonlinear stages.
>
> Instead use the idea of a **nonlinear donor/carrier**.
>
> At each input level, one source amp provides the primary nonlinear waveform.
>
> Example:
>
> ```text
> low input:
> Amp A nonlinear donor
>
> medium:
> weighted/transitioning donor strategy
>
> high:
> Amp B nonlinear donor
> ```
>
> For the first implementation, support:
>
> ```text
> nonlinear_mix = 0.0 → always Amp A donor
> nonlinear_mix = 1.0 → always Amp B donor
> ```
>
> plus an optional level-dependent morph curve.
>
> For example:
>
> ```text
> nonlinear_mix(level):
>
> -24 dB -> 0.10
> -18 dB -> 0.20
> -12 dB -> 0.35
>  -6 dB -> 0.55
>   0 dB -> 0.75
>  +6 dB -> 0.90
> ```
>
> This means the nonlinear identity progressively shifts from Amp A to Amp B as the player hits the amp harder.
>
> Do not simply use:
>
> ```python
> nonlinear = A * (1-w) + B * w
> ```
>
> for the whole waveform unless specifically operating in legacy Parallel Blend mode.
>
> Prefer a single waveform path wherever possible to reduce phase/interference artefacts.
>
> ---
>
> # Phase 5 — deterministic teacher construction
>
> Add a new module such as:
>
> ```text
> hybrid/character_blend.py
> ```
>
> The teacher builder should approximately follow:
>
> ```text
> dry input
>     ↓
> determine current input-level state
>     ↓
> select/derive nonlinear donor response
>     ↓
> apply level-dependent gain correction
>     ↓
> apply level-dependent broad EQ correction
>     ↓
> Character Blend teacher target
> ```
>
> This should be sample-continuous and free from obvious discontinuities when moving between input-level regions.
>
> The target correction must be smooth over time.
>
> Avoid rapidly changing filter coefficients sample-by-sample in a way that causes zipper noise.
>
> Practical first implementation:
>
> * estimate dry input envelope using the existing bounded causal envelope;
> * map envelope to the nearest/interpolated analysis level;
> * derive target gain and EQ for that level;
> * use smoothed parameter trajectories;
> * apply broad correction filters in blocks/windows rather than arbitrary per-sample spectral rewrites.
>
> ---
>
> # Spectral correction strategy
>
> Implement broad target EQ using a robust minimum-phase correction filter.
>
> Suggested approach:
>
> 1. derive donor magnitude response at the current/analysis level;
> 2. derive desired target magnitude response;
> 3. compute:
>
> ```text
> correction_db(f)
>     = target_eq_db(f)
>     - donor_eq_db(f)
> ```
>
> 4. smooth heavily;
> 5. clamp correction;
> 6. realise as minimum-phase FIR or low-order broad EQ;
> 7. apply to donor output.
>
> Initial correction limits:
>
> ```text
> ±6 dB maximum
> ```
>
> with a more conservative default around:
>
> ```text
> ±3 to ±4 dB
> ```
>
> Do not chase narrow resonances or phase.
>
> The goal is amplifier character, not exact impulse-response reconstruction.
>
> ---
>
> # Gain correction
>
> After selecting/rendering the nonlinear donor, apply a level-dependent gain correction so its output follows the target compression/gain curve.
>
> Conceptually:
>
> ```text
> gain_correction_db(level)
>     = GainTarget(level)
>     - GainDonor(level)
> ```
>
> Apply this smoothly.
>
> Do not independently RMS-normalise every audio block.
>
> The correction is derived from the pre-analysed transfer curves and should therefore remain deterministic.
